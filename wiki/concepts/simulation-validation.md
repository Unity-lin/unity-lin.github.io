# 시뮬레이터 검증

[[solar-ess]]에서 얻은 검증 방법. 시뮬레이션 기반 프로젝트(빗물저장, 열섬 등)에 그대로 적용할 수 있다.

## 두 가지 검증은 서로 다른 것을 잡는다
| 방법 | 확인하는 것 | 놓친 사례 |
|---|---|---|
| 단위 테스트 (23개 → 38개) | 코드가 의도대로 도는가 | 대체 계산이 발전량 절반 — 38개 모두 통과 |
| 데이터 분포 검토 | 의도가 현실과 맞는가 | — |

## 체크리스트
- **길게 돌린다**: 배터리 0% 고착 버그는 2.5일 실행 후에야 드러남. 하루·일주일·1년 단위로 돌려 본다.
- **고속 모드**: 로컬 `--interval 1`로 하루치를 몇 분에. 1년치(약 52만 건)는 노트북 30초.
- **통계 목표와 대조**: 연평균 [[peak-sun-hours]]가 공개 통계와 맞는지.
- **물리적 불가능 값**: 밤 발전, 음수, 습도 100% 초과, 정격 초과 출력이 0건인지.
- **"오류 없음"을 믿지 않는다**: 설정에서 실제 날씨가 꺼져 몇 주간 맑은 날만 쌓였지만 에러는 없었다. 쌓인 데이터를 직접 본다.
- **저장 누락 확인**: 서버가 일부 상태를 거부해 낮 데이터가 사라짐 → 생성 측에서 원본을 직접 저장.
